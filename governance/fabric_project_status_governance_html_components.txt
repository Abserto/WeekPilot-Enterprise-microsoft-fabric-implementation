This text file describes every visible component of the HTML report and links

  "V06 AI Excellence with Creative Prompting Techniques - WeekPilot: A Weekly
   Project Governance and Status Reporting Assistant grounded in Microsoft 365."

The assignment defines WeekPilot as a Microsoft 365 grounded, RAG-based,
prompt-engineered reporting assistant that produces evidence-based, executive-

the HTML file is a physical manifestation of one of those principles.


================================================================================
1. WEEKPILOT DESIGN PRINCIPLES (FROM THE ASSIGNMENT)
================================================================================

The HTML report is built on six principles taken directly from the assignment:

  P1 - Grounding: use only connected Microsoft 365 sources
       (SharePoint, Teams, Outlook, meeting transcripts, Planner, Loop).

  P2 - Evidence citation: every non-trivial claim must carry a citation in
       the [source: <name>#<date-or-anchor>] format.

  P3 - Uncertainty handling: when evidence is weak or missing, the report
       must say "Evidence not sufficient" and never guess.

  P4 - Structured output: the report has a fixed section order and a
       machine-readable footer so it can flow into Power BI / Fabric
       dashboards.

  P5 - Human-in-the-loop: the Program Manager reviews and approves the
       report before publication.

  P6 - Governance tone: neutral, factual, executive-ready. The report
       never evaluates individuals; it evaluates project activity.

These principles are referenced throughout section 3 below to explain what
each HTML block is doing and why.

3.5  Section 1 - Executive Summary
----------------------------------

  Visible elements
    Maximum of five bullet points, each carrying an in-line citation in
    the [source: ...] format.

  Underlying WeekPilot logic
    Implements Prompt C.3 of the assignment ("Executive Summary Prompt"):
      - No more than five bullets.
      - Each bullet contains a project signal, an implication and a

    model, F64 capacity, Purview blocker, CR-014, adoption gap).

4. STYLE ELEMENTS AND WHAT THEY SIGNAL
================================================================================

  Element                What the reader learns
  ---------------------- -----------------------------------------------
  .rag.green pill        Green / On track
  .rag.amber pill        Amber / At risk
  .rag.red pill          Red / Blocked or materially off track
  .rag.info pill         Neutral note (e.g. conflicting information)
  .rag.gap pill          Evidence gap - not a status, a missing input
  .cite chip             Source citation in [source: ...] format
  Numbered section head  Fixed section order defined by the system
                         prompt (Appendix D of the assignment)
  KPI value in blue      Aggregated metric, always traceable to a
                         section below
  Amber "Overdue"        Derived state, not an invented status

Colour and shape are deliberately consistent between sections so the
same evidence rule produces the same visual signal. This aligns with
the assignment's "clear headings and bullet points" style guidance.

================================================================================
6. WHEN TO REGENERATE THE HTML
================================================================================

Regenerate this HTML report for a new ISO week by running the WeekPilot
agent with:

  - The same 10 prompts from fabric_project_prompt_gallery.txt.
  - A fresh evidence bundle for the target week (SharePoint changes,
    Teams messages, Outlook events, meeting transcripts, Fabric activity
    logs, Git commits, Purview scan events).
  - A human reviewer named in the "Reviewed by" line.

Do not edit the HTML directly to change facts. Facts must always flow
from a prompt run over a validated evidence bundle. Only visual tweaks
(CSS colours, section order, wording of static labels) should be
applied by hand.
